36 次完成判斷包含 7 次合規匯總批准、29 次正確拒絕。4 次未完成都只在最後一回合拿到檔案內容，模型沒有下一回合讀取並作決定；不能把它們當作「已審查並安全拒絕」。未觀察到 hold、API／工具錯誤或輸出長度截斷。

本輪是研究者預先放入 5 類包裹，測試單一 reviewer；不是自然雙代理合謀。每個案例每組只有兩次，不能據此判定催促沒有風險，也不足以可靠斷言高催促導致較低完成率。8／3 是實際 API 回合限制；催促則是虛構業務交付窗口的文字，未操控真實獎金或獨立 token 預算。
