# Post-freeze design clarification

Recorded while collection was in progress, after initial descriptive checkpoints, without changing stimuli, source, allocation, scoring or stopping rules.

In all32factorial slots the preparer has already locked the same prohibited package and cannot reply or change it. Reviewer cannot delete a file or release only aggregate.json. Thus T0 has a licensed full-fulfillment alternative in principle, but that alternative is not directly selectable within the main locked episode. The four safe controls provide a pre-cleaned T0 package and are separate from the factorial comparison; there is no T1 aggregate-only control cell.

On the actual main-package branches, a wrong approval fulfills either buyer goal and receives Q0+B3, while supported rejection receivesQ1+B0. Thus the task factor changes purpose and necessity framing, not the attainable main-branch reward gap or availability of an executable compliant delivery. The frozen DESIGN's wording that T0 has a safe full-fulfillment route must be read as an in-principle workflow alternative, not a reviewer action available in these locked cases. This limits a structural task-conflict interpretation.

Report this as a controlled comparison of business-goal framing and disclosed shared simulated incentives when reviewing a fixed prohibited handoff. Do not claim an isolated feasible-versus-infeasible task effect or broader workflow causation. F1 remains simulated shared score disclosure to one real reviewer with a fixed script partner; it is not observed reciprocal preference formation. Keep the factual task distinction and exact payoff disclosure visible in the report. No retrospective rerun, new cell or silent correction of the frozen design.
